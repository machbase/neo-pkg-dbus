# LS DeviceString 고정 `%` 접두사 설계

## 목적

LS 사용자는 Job 화면에서 주소 본문만 입력한다. `%`는 화면이 고정 접두사로
제공하며, Job 저장값과 실제 DBus `GetDeviceData` 호출값은 `%`를 포함한 하나의
정규형을 사용한다.

예를 들어 사용자가 `MB3`을 입력하면 화면은 `%`와 `MB3`을 함께 보여 주고,
Job에는 `DeviceString:"%MB3"`을 저장한다. 실제 DBus 호출도 `%MB3`을 보내며,
`DataCount:3`이면 Tag 이름 `MB3`, `MB4`, `MB5`를 만든다.

## 입력과 정규형

- 화면의 `%`는 수정할 수 없는 접두사다.
- 사용자가 편집하는 값은 `%`를 제외한 주소 본문이다.
- 주소 본문에는 `%`를 다시 입력할 수 없고 Frontend가 이를 조용히 제거하지 않는다.
- 주소 본문은 비어 있을 수 없고 마지막은 10진수 숫자여야 한다.
- 실제 Interface 입력은 `%`와 마지막 숫자 사이에 문자가 하나 이상 있어야 한다.
- `%MB3`, `%AREA.X09`는 유효하고 `%3`, `MB3`, `%MB`, `%%MB3`는 유효하지 않다.
- Job 저장, Test Call, 수집 Job의 DBus 호출은 모두 `%`가 포함된 정규형을 쓴다.
- 기존 Job migration은 제공하지 않는다.

여기서 “문자”는 주소 본문의 한 글자 이상을 뜻한다. LS 주소 체계가 허용하는
구체적인 글자 종류는 장비가 판단하며, 패키지는 `%`와 끝 숫자 사이가 비어 있는지만
추가로 막는다.

## 제품 모듈 경계

generic 제품은 바뀌지 않는다. LS Frontend 제품 모듈이 다음 변환을 맡는다.

1. 저장된 `%MB3`을 화면 편집값 `MB3`으로 바꾼다.
2. 화면 편집값 `MB3`을 저장·호출값 `%MB3`으로 바꾼다.
3. 정규형 `%MB3`과 `DataCount`로 Tag 이름을 만든다.

공통 Job 화면은 제품 모듈이 알려 준 고정 접두사와 변환 결과만 사용한다. 공통
Backend는 LS Interface의 `DeviceString.validation.pattern`으로 저장·Test Call·수집
입력을 같은 방식으로 검증한다. LS Backend 제품 정책의 고정 Method와 Output Mapping
검증은 유지한다.

## 오류 처리

주소 본문이 비었거나 숫자로 끝나지 않으면 Job 저장과 Test Call을 허용하지 않는다.
정규형이 `%`로 시작하지 않거나 `%`와 마지막 숫자 사이가 비어 있어도 같은
`JOB_INVALID` 입력 오류로 처리한다. 잘못된 주소로 임시 Tag를 만들지 않는다.

## 검증

- `MB3` 입력이 `%MB3`으로 저장·호출되는지 확인한다.
- 기존 `%MB3` 저장값을 편집할 때 입력에는 `MB3`만 보이는지 확인한다.
- `%MB3`, `%AREA.X09`는 Interface 검증과 Tag 생성을 모두 통과하는지 확인한다.
- `%3`, `MB3`, `%MB`, `%%MB3`는 Interface 검증과 Tag 생성을 모두 통과하지
  못하는지 확인한다.
- 수동으로 바꾼 Tag 이름 보존과 DataCount 증감 규칙이 그대로인지 확인한다.
- generic 제품의 입력, Interface 관리, Method Call 편집 동작이 변하지 않는지 확인한다.
